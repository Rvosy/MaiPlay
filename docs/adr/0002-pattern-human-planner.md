# ADR-0002：分离配置候选与动作搜索，保留基线对照

日期：2026-10-08

状态：已采纳，开发版已接入试验入口；尚未发布

## 背景

`NormalHandPlanner` 已能生成可回放的双手轨迹，并通过实际输入核验整首谱面。它把动作构造、手法识别、分手搜索和局部修复集中在同一实现中，多种扫键策略分别求解整首谱面。继续在这条路径中增加配置规则，会让局部打法组合、运动约束和结果归因更难单独检查。

高难度规划需要比较前后衔接和持续占手。同一首谱面中，不同段落可以分别采用交互、点按或扫键；一种整曲策略的成绩不足以说明各段候选是否组合得当。与此同时，已有判定器和基线结果仍需保留，用于区分搜索变化与基础规则变化。

## 决定

新增 `HumanPlanner`，将谱面需求、配置识别、局部打法候选、运动模型和最终回放分开。采用直接的数据记录与调用，暂不引入规则语言或通用插件框架。各层职责及源码入口由[配置与动作规划指南](../HUMAN-PLANNER.md#实现分工)统一维护。

配置只提供搜索候选，每段保留自由分手路径。各段在同一次 beam search 中衔接，双手当前动作与持续占用跨段保留；允许因后续需求选择另一种前段候选。有限搜索宽度和状态合并是性能取舍，不承诺全局最优，也不把识别标签视为唯一正确打法。

基线和新求解器共用接触轨迹编译器。四指几何、Slide 局部校准、Wifi 接触路径和输入生成保持同一来源，避免两个规划器悄然维护不同的接触规则。局部和整曲核验始终使用现有 `PlaybackSession`，规划器不改判定窗口、不写成绩。

将归一化手位转换为估算毫米距离，集中处理速度检查与动作成本。该尺度和速度参数明确属于模型假设。当前状态只描述二维手位、占用和相对左右关系；没有足够标定数据时，不加入疲劳、完整手臂姿态或碰撞模型。模型范围和指标含义见[运动模型说明](../HUMAN-PLANNER.md#运动模型的范围)。

整曲实际判定提供有限的时机反馈，再交回原搜索流程重算。反馈结果仍与原方案比较，并重新核验整曲。恢复路径与正常求解共用约束，不建立绕过判定的修复通道。

`NormalHandPlanner` 保留为默认求解器，新实现通过界面的试验选项和 `--plan-human` 启用。`--compare-planners` 对同一批谱面运行两者，按等级保存判定结果和动作指标；报告包含谱面与程序集指纹，统计文件可以随源码提交，曲库和轨迹不随报告提交。默认入口的后续变更需由对应等级的对照结果和回放验收支持。

## 未采用的方案

- 直接替换或删除基线：会失去稳定的对照入口，也无法分辨结构调整与搜索取舍带来的变化。
- 为每种社区配置编写固定手序：同一配置可能有多种叫法与打法，手序还取决于前后衔接及另一手是否被占用。
- 只按全 CP 选择方案：无法比较同判定结果下的移动代价，也会掩盖超出当前运动约束的轨迹。
- 立即建立完整人体仿真：当前缺少机台、手臂与动作测量，复杂状态会增加无法核验的假设。

## 影响

新打法可先增加局部候选，再用占手、运动约束和整曲判定共同筛选。共享接触或判定路径的修改仍需回归基线；仅调整新搜索器时，可先运行局部行为测试和目标等级对照。

二维速度约束更严格，候选与搜索预算也不同，新实现可能在部分谱面退步。报告必须同时记录改善、退步、异常和未覆盖范围。全 CP 结果只证明生成输入满足当前判定规则，不证明真人能够按该轨迹完成。

使用命令、模型限制和报告解释由[配置与动作规划指南](../HUMAN-PLANNER.md)维护；基础输入契约继续由[游玩机制规范](../specs/gameplay.md)维护。
