# 游玩机制与算法输入契约

状态：基础机制已在 0.2.0 接入，验收与发布状态见 [0.2.0 验收记录](../GAMEPLAY-VALIDATION.md)。手部回放与初版手顺求解已接入当前开发版，尚未发布，使用方式及验证结果见[输入回放指南](../INPUT-REPLAY.md)。

## 产品范围

MaiPlay 是本地 Simai 游玩器。实际游玩的输入由程序提供，判定、音符状态、成绩、画面和音效按输入结果运行。初版手顺求解输出双手轨迹，经接触映射进入同一判定器。

本阶段完成现代 DX 基础机制：Tap、Hold、Touch、TouchHold、所有标准 Slide 形状、Wifi、连接与同头分叉 Slide，以及对应的 Break、EX、EACH、TouchGroup 和烟花行为。谱面修饰的合法组合按固定上游版本确认，不能只在解析或皮肤层识别却省略判定。

Classic 规则、Mine、自定义轨迹等上游扩展暂不作为现代 DX 基础机制的完成条件；遇到未支持的语法须明确指出，不能静默跳过。真人设备接入、人体运动标定、联网和曲库管理不属于本阶段。

上游取舍见 [ADR-0001](../adr/0001-upstream-gameplay.md)。源码定位、版本与核验进度见[上游研究记录](../../research/upstream-gameplay.md)。

## 输入和时间

- 游玩核心接受按时间排序的按钮和触摸区域状态变化。事件至少包含谱面时间、输入通道、区域以及按下或释放；同刻顺序有明确且稳定的定义。
- 外键 1～8 与触摸 A1～A8、B1～B8、C、D1～D8、E1～E8 分别建模。哪些 Note 可以接受哪种通道、同区多个 Note 的消费顺序及按钮和触摸的关系按上游核验。
- 记录区域持续状态与触发边沿。持续按住不等于不断重新按下；释放必须能影响 Hold 和 Slide。多个接触源覆盖同一区时，移走一个接触源不能误释放仍被覆盖的区域。
- 输入源不能指定“命中某个 Note”或直接写入判定等级、完成状态、分数。它只能提供操作，判定器负责决定操作影响哪些音符。
- 输入日志、谱面和判定使用同一时间基准，歌曲 first、判定偏移和显示偏移各自只应用一次。帧制规则的采样时点与边界顺序必须确定，不依赖 UI 刷新率。
- 实时播放由音频位置驱动；离线验证按同一逻辑时间推进。UI 跳帧时不能跳过输入、释放或判定期限。相同谱面、规则版本和输入序列，逐步推进与批量推进得到相同的最终结果和事件顺序。
- 暂停不推进逻辑时间；重开清除区域状态、输入游标、音符状态、统计和持续音效。时间轴跳转重建目标时刻的完整状态；具体交互见[播放界面契约](player-settings.md)。

接口采用当前需要的简单数据结构与调用方式，不要求输入设备插件、服务总线或通用事件框架。

## 区域与接触

逻辑区域必须可被输入事件独立激活，也必须能在诊断视图中显示当前 ON/OFF。只有 Touch 的显示坐标不算实现区域判定。

为后续算法保留一个可验证的接触入口：带时间的接触位置、接触范围和离屏状态可以转换成区域事件，并由同一判定器消费。屏幕接触与外键接触分开，不能仅按最近的区域中心选一个区域，丢失覆盖多个区域的情况。

接触边界必须来自固定参考或明确记录的近似模型。显示圆孔、画面判定圈、传感器有效边界和外键尺寸不能混作一个半径。毫米尺度和人体约束不是完成逻辑判定的前提；仍使用归一化近似的部分须在研究记录中标明。C1/C2 只有取得物理依据后才进一步拆分，逻辑层按上游合并为 C。

直接提交区域事件用于隔离验证游戏规则；接触位置转换用于验证几何映射。两者共用后续判定，不维护两套规则。

手部回放可提交左右手轨迹，以及每只手上多个独立接触部位。轨迹按逻辑网格和原始关键帧转换为同一接触输入；空中移动不生成触区输入，原始短脉冲不能因轨迹插值丢失。手位标记只表示手的位置；覆盖范围仍由接触几何和判定器当前输入决定。来源归属须保留到当前采样，包括被锁存的短脉冲；多个部位或双手覆盖时，释放其中一个不能清掉其他来源。格式和运行方式见[输入回放指南](../INPUT-REPLAY.md)。

## 音符判定

| 机制 | 必须验证的行为 |
|---|---|
| Tap / 星头 | 有效输入通道、提前和延后窗口、各档 Perfect/Great/Good/Miss、Fast/Late、同区音符匹配及输入消费 |
| Touch | 独立时间窗、过早接触的处理、持续激活与边沿语义、同区排序，不能套用 Tap 窗口 |
| Hold | 头判、有效持续区间、头尾忽略范围、短 Hold、释放容错、重新按下、按压比例与最终等级 |
| TouchHold | Touch 头判与自身持续规则、短 TouchHold、释放及重新接触，不能直接等同普通 Hold |
| Slide | 判定区队列、OR 区组、顺序、按下/释放、跳区、尾区规则、可开始判定的时刻、提前结束和最终时间窗 |
| Wifi | 三路判定队列及整体完成条件，不能只检查一条中心线或星星动画是否结束 |
| 连接 / 分叉 Slide | 各段时序与进度传递、同时激活的轨道、共享区域输入、头部和轨道独立归属 |
| TouchGroup | 组的构造、成功成员阈值、判定继承和触发时机，不能只实现同区视觉边框 |
| Break / EX / EACH / 烟花 | 判定保护及例外、计分归属、同时关系、音效与效果触发；不要把显示修饰统一当成判定规则 |

时间窗数值、开闭边界、采样顺序与状态转移须从源码调用链确认，定位到固定提交的文件和符号。最终常量由实现代码持有，本文不复制整套常量表。用边界内、边界点、边界外的输入用例验证，不能只验证常量存在。

同一操作可能影响多个正在进行的音符。滑过其他 Note、提前完成 Slide、Hold 占区等干扰必须来自全局区域状态；不能将每个 Note 的输入隔离后各自宣告成功。

## 两种模式

### Auto Play

保留理想播放模式，用于展示与检查谱面。可沿用固定上游的自动判定捷径，但须与实际输入判定路径清楚区分。其全 CP 不能作为输入判定正确或双手可执行的证据。

### 算法游玩

使用真正的输入判定路径。既可回放输入日志，也可为当前谱面求解手顺。默认普通双押分给两只手；不主动用单手掌盖、内外键复合来合并普通击打。另一手在整个 Touch CP 窗内被长音符或滑动占用时，空闲手可以依次击打两个 Touch。四指接触自然覆盖相邻传感区仍按实际几何处理。星头和滑动可独立分手，持续占手必须约束后续动作。

同键连续单 Tap 默认优先使用同手；达到 `NormalHandPlanner.FastRepeatInterval` 规定的速度且连续至少三下时，优先双手交互。这个偏好服从占手和移动约束，不强制把单手无法衔接的慢连打分给同手。

同方向相邻键构成的扫键和连续转圈属于常规打法。速度按解析后的音符间隔判断，包含 BPM、细分和变速的影响。规划器应考虑持续接触的扫键轨迹，按四指接触进入外键的时刻对齐音符；不能把每一步都当成静止点按后的跨键跳跃。快速段尝试单手扫过或完整转圈，较慢转圈偏向左右半圈接力；具体阈值和候选选择见[输入回放指南](../INPUT-REPLAY.md#求解手顺)。候选轨迹仍需检查占手、移动时间并进行整曲核验，防止扫过其他键时提前判定。快速 Slide 可在判定窗口内调整动作时长，必须实际经过中间判定区，不得跳过区队列。

扫键识别按时间和位置处理单键流、并行双键流及其衔接，不依赖曲目名或 ID。持续经过空键也必须生成真实接触，按弧长约束移动速度并核验误触。新增手法候选需保留此前已通过的时机调整，不能因换一种动作表示而丢弃这些调整。

规划输出不得修改判定规则或直接写成绩。完整动作需通过整曲实际输入核验；未解音符允许保留缺口并继续生成。主程序可播放未完成方案，并显示缺口与非 CP 位置。已有接触自然完成或 Touch 组判完成的音符不计为缺口。局部时机调整仍需重新回放整首验证，不能为了取得全 CP 自动开启特殊技巧或无限放大接触面。

没有输入时，由各音符状态机自然产生 Miss。禁止在构造会话时把全部最终结果锁定为 Miss，导致后来即使有输入也不能改变结果。

输入日志可经简单文件或开发入口加载，不建设专用编辑器。格式由实现定义并记录，只保留重放所需的信息与规则版本。

## 输出与表现

每个最终判定至少可追溯到音符、等级、Fast/Late、判定时刻及适用的时间偏差。长音符和组继承判定的时间含义分别记录，不能伪造为一次 Tap 的偏差。Slide 需要能检查区段推进与最终失败原因。

同一最终结果只更新一次 Combo、判定分布与成绩；重开后归零。DX 减分达成率沿用[达成率契约](achievement.md)，接收判定器的实际等级。DX 分数及 Break 子档等统计按固定上游确认，不能以命中比例替代游戏成绩。

画面和音效消费实际状态变化，能够呈现 Perfect 各档、Great、Good、Miss、Fast/Late 及长音符过程。流速只影响入场显示，不改变命中时间或 Slide 谱面移动时长。保留已有皮肤、歌曲导入和音频功能。

## 完成条件

接入打法规划算法前，以下项目全部通过：

1. 固定上游来源，建立机制到实现、行为测试的对应记录；分歧有明确选择，不混合两套互相矛盾的规则。
2. 每种基础音符都有成功、偏早、偏晚、无输入与适用的错误区域用例。手写输入必须能改变最终判定，无法用 Auto Play 预设结果代替。
3. Hold/TouchHold 覆盖短音符、间断与恢复；Slide 覆盖全部标准模板的区队列、旋转/镜像、跳区/释放、连接、分叉、Wifi 和误触干扰；TouchGroup 覆盖阈值边界与继承。
4. 输入顺序、同刻事件、逻辑采样、跨帧推进、暂停和重开都有代表性回归。边界预期来自独立源码核验或上游运行结果，不能调用被测实现生成预期值。
5. 用最小输入日志在窗口中观察成功、Fast/Late 和 Miss，逐项核对判定、中央达成率、音效与传感区状态；至少有成功推进的 Slide 和失败的 Slide。
6. 现有四首歌曲的全部 18 个难度、两种模式、五套皮肤和基本音频控制无回归。复杂真实谱面无需在没有规划器的情况下自动生成可行输入，但必须能载入、推进并完成结算。
7. 规划器优化后按难度运行本地整库，当前以全部 Expert 为基准；新增覆盖逐步扩展至其他难度。保存逐谱达成率、Rating、B50、缺口与非 CP 位置，并和上一轮比较。部分完成方案也必须回放至曲末，不能只统计搜索成功的谱面。
8. 已实现、已验证、已发布分别记录。存在未完成的基础机制时不能称“完整游玩机制已完成”。

只围绕上述行为和已知问题编写测试，不为模块数量、代码布局或重复内部校验编写测试。
